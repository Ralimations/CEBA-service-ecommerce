## Product assumptions and policy decisions

1. **Currency and time:** PHP displayed in pesos, money stored as centavos, event dates interpreted in Asia/Manila, operational timestamps UTC. Identity and defaults are centralized.
2. **Availability:** A provider handles one event per calendar day across all services. Unspecified dates are available. A pending request does not hold a date; each provider's acceptance reserves it transactionally. Cancellation releases all booking reservations. Accepted unpaid reservations do not time out automatically.
3. **Booking prices:** Packages and add-ons are fixed prices. Guest count is recorded, not multiplied into price. Bookings snapshot accepted terms and amounts; changes to future listings do not alter them.
4. **Fees:** Default platform fee is 5%, deducted from the discounted booking allocation rather than added at checkout. The final item absorbs centavo rounding differences so allocations and fees conserve the exact total. All values are simulated.
5. **Bundle agreements:** Each bundle selects one package per unique provider. All suppliers must accept current terms before publication. Material bundle changes reset approvals. All providers must accept a customer request before checkout; all must complete Gate 2 before ordinary escrow release.
6. **Gate timing:** Demo mode allows future bookings to pass the gates immediately. Set `DEMO_HANDSHAKE_ANYTIME=false` to require the event date. Tokens expire after 30 minutes, allow five failed attempts, and must be regenerated after expiry/lockout. Codes exist as plaintext only when issued to their proper party; the database holds hashes.
7. **Cancellation/disputes:** Unpaid cancellation is immediate; cancellation after payment opens a dispute and freezes funds. Admins may refund the full booking or release it exceptionally only with confirmation, a reason, and audit logging. No automatic percentage penalties or partial refunds are assumed.
8. **Loyalty and referrals:** Rank uses completed parent-booking count (default Silver 3, Gold 8, Platinum 15). A multi-provider bundle counts once. Referral rewards occur once at the first completion; default reward is a PHP 500 owned voucher per party. Welcome defaults are 10% off, PHP 1,500 cap, PHP 3,000 minimum, first paid booking only.
9. **Trust versus promotion:** Trusted/Best Service derive from rating, completed jobs, unresolved disputes, and admin controls. VIP/Sponsored are paid visibility. Explicit price/rating sorts preserve those sorts; only Recommended mixes visibility weights. Badge thresholds are global; category-percentile awards are not implemented.
10. **Subscriptions:** VIP is a simulated 30-day period, not automatically recurring billing. Downgrading ends the current VIP benefit. Existing portfolio rows are retained when downgrading; the Classic limit prevents additional entries beyond its allowance.
11. **Notifications:** In-app events persist immediately. Reminder generation happens during visits; no guarantee of delivery while nobody visits. Pages refresh on navigation and actions, not through a realtime connection.
12. **Support and media:** FAQ answers are deterministic. Tickets have an admin response field rather than a live messaging thread. Images use local files or supplied URLs. Seed businesses, names, ratings, reviews, and history are fictional demonstration records.
13. **Architecture:** The native SQLite repository is a deliberate alternative to an ORM. Migration 1 is idempotent for fresh local databases; future schema changes need new versioned migrations. The server is a single-process local prototype with synchronous SQLite access.

## Validation record

Performed on Windows with Node 24.19.0 and local headless Chrome:

- `npm run typecheck`: passes, generating Next route types before checking.
- `npm run lint`: passes.
- `npm run format:check`: passes.
- `npm test`: **21 domain integration tests pass** against an isolated in-memory database. Coverage includes ownership, registration, session security, state transitions, pricing and fees, voucher restrictions, reservation conflicts, bundles, QR expiry/rotation/reuse/lockout, referral idempotence, dispute resolution, immutable ledgers, recommendation behavior, subscription expiry, settings, and reminder idempotence.
- `npm run test:e2e`: **six browser scenarios pass** against a separately seeded database: bundle curation/approvals/publication/request; voucher/VIP/featured purchase; marketplace discovery/responsiveness; registration-to-review lifecycle through both gates; provider service/package/calendar/profile workflow; admin support/refund/category/settings workflow.
- `npm run test:smoke`: **53 public and authenticated routes pass**, plus role redirects and cross-origin rejection. Executed against development and built production servers.
- `npm run build`: passes. Built server starts and serves the authenticated route suite successfully.
- `db:reset`, `db:migrate`, and repeated `db:seed`: pass on an isolated database; repeated seed correctly skips existing records.
- Captured and inspected responsive screenshots, including home, provider workspace, administrator workspace, completed booking, and a multi-provider booking. Key layouts tested at 1440px, 768px, and 390px. Artifacts live in the ignored `artifacts` directory.

## Known issues and next work

No blocking failure remains in the tested Phase 1 workflows. Coverage is not exhaustive across browsers, assistive technologies, concurrency, or hostile production traffic. The limitations above are intentional local-prototype boundaries rather than claims of completed external integrations.

Next: review business rules with the product owner; select production payment/refund and scheduling policies; integrate payments and signed webhooks with reconciliation; add camera scanning, background delivery, verified email/reset, direct uploads, operational database migrations, backups and observability; then validate deployment security, accessibility, load, and recovery before any public launch. Decide the intended PWA meaning before implementing installation/offline behavior.
